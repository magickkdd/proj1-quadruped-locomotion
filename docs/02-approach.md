# 项目一可行方案：复杂地形下四足机器人鲁棒行走

## 1. 结论

项目一不自行从零写训练框架，直接复现 LocoWiki 已收录的开源代码，在此基础上做系统性实验。

**主复现对象：LeggedGym-Ex（Go2 locomotion 任务）**

- 仓库：https://github.com/lupinjia/LeggedGym-Ex
- 说明：https://locowiki.github.io/open-source.html?path=network-open-source%2Fdevelopment-tools%2Fleggedgym-ex.md
- 理由：延续 `legged_gym` 的 API 和目录结构，已有 Go2 任务、地形课程、域随机化、系统辨识、Teacher-Student 等方法示例，后续做对照不需要重构代码。

**第二阶段对照对象：amp_go2（AMP + 楼梯）**

- 仓库：https://github.com/ak1raljl/amp_go2
- 说明：https://locowiki.github.io/open-source.html?path=network-open-source%2Fpaper-reproductions%2Famp-go2.md
- 楼梯实验：https://locowiki.github.io/open-source.html?path=network-open-source%2Fpaper-reproductions%2Fgo2-amp-stairs.md
- 理由：提供 AMP 风格奖励和楼梯地形任务，可作为“手工奖励 vs 风格奖励”的对照。

**备选（仅在主仓库无法运行时启用）：**

| 仓库 | 用途 | 说明页 |
|---|---|---|
| unitree_rl_gym | 官方 Go2 训练基线 | 官网工具箱 |
| legged_gym | 最稳定的原始基线 | https://github.com/leggedrobotics/legged_gym |
| My_unitree_go2_gym | Go2 步态与跳跃实验参考 | https://locowiki.github.io/open-source.html?path=network-open-source%2Fpaper-reproductions%2Fgo2-trot-gait-control.md |
| DreamWaQ 高台版 | 无视觉高台攀爬对照 | https://locowiki.github.io/open-source.html?path=network-open-source%2Fpaper-reproductions%2Fm20-dreamwaq-highplatform.md |

**明确不选：**

- `go2-supermimic` / `go2w-supermimic`：世界模型路线与项目二重叠，且会分散项目一的实验预算，仅作为相关工作引用。
- 任何竞赛完整方案：与目标岗位能力要求不匹配，且不属于通用 locomotion 研究。

## 2. 项目定位

**不做的：**

- 不承诺真机部署、不承诺量产
- 不追求高动态特技动作
- 不堆叠多个算法名

**要回答的问题：**

> 在固定 PPO 框架和固定训练预算下，地形课程、域随机化、执行器建模和观测历史分别对四足机器人的复杂地形通过率、速度跟踪精度和抗扰动能力贡献多大？

这个问题有明确的改动项和评测指标，可以用改前改后对比回答，适合作为求职项目的核心叙事。

## 3. 计算平台与 A100 可行性判断

### 3.1 能跑的部分

| 组件 | A100 可用性 | 说明 |
|---|---|---|
| Isaac Gym Preview 4 | 可用 | A100 为 Ampere `sm_80`，在支持范围内；按官方 Dockerfile 固定 Python 3.8 + PyTorch 2.4.1+cu121 |
| LeggedGym-Ex 的 Isaac Gym 后端 | 主路径 | 单卡训练吞吐高，依赖最少 |
| Genesis 后端 | 可尝试 | 作为 Isaac Gym 环境异常时的备选 |
| Isaac Sim 后端 | 不建议 | A100 无 RT Core，渲染相关功能有风险；训练任务不做主路径 |
| MuJoCo / MJLab | 可用 | 用于策略回放与 sim2sim 验证，不作为大规模并行训练主路径 |

### 3.2 平台上的并行方式

平台每个训练任务独占所选资源，不需要自己在命令里切卡。开发机不可用时，环境构建、依赖排查和小规模调试都用短时训练任务完成。正确用法：

- 主实验：一个 `NvidiaA100-1-80G` 训练任务
- 并行对照：再提交一个 `NvidiaA100-1-80G` 任务，写不同的 `/data/proj1/runs/<run-id>/`
- 不使用 A100×8，也不做跨卡模型并行；Isaac Gym 单卡即可，多卡只会更快消耗算力点

启动命令按平台约定基于 `/code/workspace`，例如：

```bash
bash /code/workspace/scripts/train_job.sh
```

真实参数放在脚本与平台超参数里，避免超过 500 字符限制。

### 3.3 显存与吞吐的现实约束

- A100 80 GB，`num_envs` 先测 1024 / 2048 / 4096 三档。
- 选择标准：显存峰值 ≤ 64 GB，且 `total_fps` 最高；同时记录算力点单价，吞吐高但点数贵时要算总成本。
- A100 的 FP32 算力远高于 T4，但任务按算力点计费；训练时长和点数都要写进实验日志，这是简历里可以写的真实工程约束。

### 3.4 第一条硬性门槛

在投入任何实验设计之前，必须先完成：

> 平台训练任务、`NvidiaA100-1-80G`、`num_envs=1024`、`--headless`、跑通 100 次迭代、TensorBoard 有 reward 曲线、显存无 OOM，并记录任务 ID 与算力点。

这一条不通过，不进入任何对照实验。

## 4. 环境搭建清单

### 4.1 版本固定

在项目根目录建立 `docs/env-lock.md`，记录：

- 平台任务 ID、资源规格（A100-1-80G）、算力点
- 镜像名或 `conda-pack` 包 sha256
- 操作系统版本
- NVIDIA 驱动版本
- CUDA 版本
- Python 版本
- PyTorch 版本与 CUDA 编译版本
- Isaac Gym 版本（Preview 4）
- 仓库 commit hash
- `pip freeze` 输出

不固定版本，后续所有实验都无法复现。

### 4.2 搭建顺序

1. 提交探测任务（1×A100-1-80G、官方镜像）：确认 `nvidia-smi`、Python 版本、能否访问 pypi/conda、`/data` 与 `/tmp` 空间
2. 把 Isaac Gym Preview 4 安装包上传到 `/data/proj1/env/`
3. 提交一次性环境构建任务，创建 Python 3.8 环境（建在 `/tmp`，避免云盘 I/O）
4. 安装 PyTorch 2.4.1+cu121 与 torchvision 0.19.1+cu121
5. 先装 numpy 1.24.1，修复 `np.float` 后从 `/data` 的本地包安装 Isaac Gym（`pip install -e <包路径>/isaacgym/python`）
6. clone LeggedGym-Ex 到 `third_party/`，读取其 README 的安装说明
7. 安装仓库自身依赖，运行最小任务（平地、少量环境、短迭代）
8. `conda-pack` 打包到 `/data/proj1/env/`，记录 sha256 与 env-lock
9. 提交 100 迭代冒烟任务，确认解包、`conda-unpack`、激活、TensorBoard 都正常
10. 代码固化到 Git；后续每次训练任务只改代码/配置并重新提交

### 4.3 仓库健康检查

复现前逐项确认并记录：

- 最后一次 commit 时间
- LICENSE 是否存在、是否允许二次开发与展示
- Go2 资产是否自带，还是需要从 Unitree 仓库拉取
- 默认 `num_envs`、`max_iterations`、地形配置
- 是否有硬编码绝对路径
- 是否有未提交的本地修改
- issue 区是否有未解决的安装问题
- 平台任务容器内能否 clone 仓库、访问外网

如果仓库缺少 LICENSE，只在本地研究使用，不在简历中声称“开源贡献”。

## 5. 三阶段执行计划

### M0：复现基线（必须先完成）

目标：证明原仓库能在平台 A100-1-80G 上稳定训练，并产出可对比的基线数字。

步骤：

1. 提交平地训练任务，记录 FPS、显存、100 次迭代耗时、算力点
2. 提交粗糙地形任务，确认地形课程生效
3. 从 `/data` 取 checkpoint，用 `play.py` 回放
4. 保存 TensorBoard 日志、配置快照、commit hash、任务 ID
5. 写一页“基线复现记录”，包含实际遇到的报错与解决方式

M0 验收：

- 平地与粗糙地形各有一份完整训练曲线
- 主基线至少跑完一次完整训练；算力允许时再补第二个种子
- 回放画面与训练 reward 一致，不存在“指标好看但动作异常”
- 训练任务可从 `/data` 的 checkpoint 续训

### M1：问题定位与轻量对照（够用即可）

这不是论文，不需要完整的消融矩阵。目标是产出一个**能讲清楚的问题解决故事**和一个**可对比的数字**。

优先级从高到低，做完上一档再考虑下一档：

**P0（必须）：**

| 编号 | 变量 | 对照设置 | 用途 |
|---|---|---|---|
| C1 | 地形难度 | 平地 vs 粗糙地形 + 课程 | 证明系统确实在解决复杂地形问题 |
| C2 | 至少一个真实故障的修复前后对比 | 如：策略抖动/频繁摔倒/训练发散 | 面试时讲“我怎么定位并修好”的故事 |

**P1（有余力再做，二选一）：**

| 编号 | 变量 | 对照设置 | 用途 |
|---|---|---|---|
| C3 | 域随机化范围 | 窄范围 vs 宽范围 | 说明鲁棒性与性能的取舍 |
| C4 | 执行器建模 | 理想 PD vs 力矩-速度饱和 | 说明仿真真实性对策略的影响 |

**明确不做：** 六组以上的完整消融、多因素交叉实验、论文式统计显著性检验。这些属于科研项目，不是求职项目。

每次实验只需记录：改了什么、结果如何、为什么。不需要写成论文表格。

**唯一纪律：一次只改一个条件。** 同时改三处，出了问题说不清原因，面试时也讲不明白。

### M2：扩展与对照（有余力再做）

- 用 `amp_go2` 跑 AMP + 楼梯任务，与 M1 的手工奖励基线对比动作自然度和能耗
- 用 MuJoCo 或 MJLab 做一次 sim2sim 回放，记录策略跨仿真器的性能下降幅度
- 可选：用 `DreamWaQ 高台版` 作为高障碍课程学习对照

M2 是加分项，不是必需项。M1 没做扎实之前不进入 M2。

## 6. 评测协议

### 6.1 固定评测条件

- 同一套评测地形种子
- 同一组速度指令采样范围
- 同一评测回合长度
- 每档地形至少 100 个 episode
- 所有对照方法使用同一评测脚本

### 6.2 指标

| 类别 | 指标 |
|---|---|
| 任务 | 速度跟踪误差、指定地形通过率、成功率、平均存活时长 |
| 稳定性 | 摔倒率、姿态角超限比例、关节限位触发次数 |
| 动作质量 | 峰值力矩、平均力矩、动作变化率、足端滑动 |
| 效率 | 训练 FPS、总 GPU-hours、显存峰值、单位性能训练成本 |
| 泛化 | 未见地形难度、未见摩擦系数、外加扰动下的性能保持率 |

### 6.3 结果呈现

- 主表：方法 × 指标，含均值和标准差
- 曲线：训练 reward、分项 reward、地形课程等级
- 失败案例：至少 3 个典型失败 episode，附根因分析
- 结论必须写明“仿真结果，未做真机验证”

## 7. 验收标准

项目一算完成，需要同时满足：

1. 主仓库在平台 A100-1-80G 上可稳定训练，环境搭建与封装过程有完整记录
2. 平地与粗糙地形基线各有一份完整结果
3. 至少完成 2 组能说明问题的对照（C1 + C2）
4. 有统一评测脚本，所有方法在同一条件下评测
5. 有失败案例和根因分析，不是只放成功视频
6. 有可运行命令、配置文件、commit hash、任务 ID
7. 有可复用的镜像或 `conda-pack` 环境包，并能从 checkpoint 续训
8. 有 3–5 分钟演示视频，包含成功与失败
9. 简历中每个数字都能在日志或表格中查到

## 8. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 平台默认镜像 Python 3.11 跑不了 Isaac Gym | import 报错 | 用 Python 3.8 环境包或自定义镜像；先用最小脚本验证 |
| 任务内无法下载 Isaac Gym | 安装包拉不下来 | 提前上传到 `/data/proj1/env/`，从本地安装 |
| 仓库依赖腐烂 | 安装失败、API 变更 | 记录 commit；必要时切到原始 `legged_gym` + 官方 Go2 资产 |
| 显存不足 | OOM | 降低 `num_envs` 至 1024/2048 |
| 任务 168 小时到期 | 训练被中断 | 定期存 checkpoint，分段训练，从 `/data` 续训 |
| 任务排队 | 长时间不开始 | 换资源规格或错峰提交；本地 T4 先跑通链路 |
| 训练太慢/点数消耗快 | 单次实验成本高 | 降低环境数与迭代数，先跑短周期对照，再对最优配置做长训练 |
| 指标好看但动作异常 | reward 上涨、回放抖动 | 以回放和视频为一等验收标准，不只看曲线 |
| 结果不可复现 | 换机器后数字不一致 | 固定种子、配置、版本、环境包，保存完整运行日志 |
| 仓库无许可证 | 无法公开代码 | 只做本地复现，公开部分只放自己的实验配置与报告 |

## 9. 项目一通俗介绍

### 9.1 一句话

教一只虚拟机器狗在烂路上走路，走不稳的时候能自己找出原因。

### 9.2 三句话说清

1. 把 Unitree Go2 放进 Isaac Gym，让它自己在仿真里练走路，目标是跟住速度和转向指令、不摔倒。
2. 训练地形从平地逐步加难到斜坡、台阶、坑洼；同时随机改摩擦、重量、电机力气，逼它适应不同地面。
3. 我在 Intern Discovery 的 A100 训练任务上把训练跑通，遇到问题就查曲线、看回放、改配置，最后留下可复现的配置和一组真实数字。

### 9.3 为什么这算项目

- 跑通别人的代码只值一分，能定位并修好问题才值钱。
- 企业要的是“训练能跑、指标能看、问题能修”，不是能背算法名。
- 所以交付四样东西：能走的策略、能复现的配置、能拿出手的数字、一个讲得清的排障过程。

### 9.4 面试口头版

> 我做的是四足机器人在复杂地形下的强化学习运动控制。用 Isaac Gym 搭 Go2 的训练环境，先复现平地速度跟踪，再加地形难度和随机化。主要工作是把训练跑稳、把出现的问题定位修好，并留下改前改后的对比。结论只在仿真范围内。
