## 1. 项目核心目标与验收标准

### 1.1 核心目标

在 Intern Discovery 的 A100-1-80G 训练任务上复现 Go2 四足强化学习训练链路，得到一份可信的复杂地形行走性能数据，并完成至少一个真实故障的定位与修复。

### 1.2 能力目标

- 能在 Isaac Gym 中稳定启动 Go2 训练，不 OOM、不崩溃
- 能读懂并调整观测、奖励、地形课程、域随机化配置
- 能独立写评测脚本，产出可对比指标
- 能从一个异常现象出发，定位到配置或代码层面的根因
- 能把 Python 3.8 环境封装成可复用镜像或 `conda-pack` 环境包
- 能让训练脚本定期保存 checkpoint，并从 checkpoint 继续训练
- 所有产物写入 `/data`，任务结束后可完整取回

### 1.3 范围边界

**做：**

- 平地与粗糙地形两组训练
- 至少一次故障定位与修复
- 统一评测脚本与结果表
- 平台环境封装（镜像或 conda-pack）、断点续训与产物落盘
- 完整复现记录与演示视频

**不做：**

- 真机部署
- 新算法提出
- 多机器人平台适配
- 与 SOTA 刷分对比

### 1.4 验收标准

| 级别 | 标准 | 判定方式 |
|---|---|---|
| Must | 主仓库在 A100-1-80G 的训练任务中跑通 ≥100 次迭代且显存不 OOM | 平台任务日志 + `nvidia-smi` |
| Must | 平地与粗糙地形各有一份完整训练结果 | TensorBoard 曲线 + `/data` 中的 checkpoint |
| Must | 有一套统一评测脚本，能输出指标表 | 脚本可重跑，输出 CSV |
| Must | 至少一个故障完成“现象 → 排查 → 根因 → 修复 → 对比”闭环 | 故障记录文档 + 改前改后数据 |
| Must | 训练任务能从 `/data` 的 checkpoint 续训并继续写曲线 | 续训任务日志 + 曲线 |
| Must | 环境可复用：镜像或 `conda-pack` 环境包能重新拉起训练 | 重新提交任务成功 |
| Must | 结论明确标注为仿真结果 | README 声明 |
| Should | 主基线有第二个随机种子 | 两份日志 |
| Should | 有 3–5 分钟演示视频，含失败片段 | 视频文件 |
| Should | 记录每个任务的算力点与 GPU 小时 | 成本表 |
| Won't | 真机、量产、论文级对比 | 不评估 |

### 1.5 指标定义

| 指标 | 定义 | 单位 |
|---|---|---|
| 速度跟踪误差 | 指令速度与实际速度的均方根误差 | m/s |
| 地形通过率 | 成功通过指定地形难度的 episode 占比 | % |
| 摔倒率 | 触发终止条件的 episode 占比 | % |
| 训练吞吐 | 每秒环境步数 total_fps | steps/s |
| 显存峰值 | 训练期间 GPU 显存最大值 | GB |
| 单组成本 | 单次完整训练消耗的 GPU 小时 | GPU-h |
| 算力点消耗 | 平台任务详情页显示的点数 | 点 |

### 2.5 环境准备步骤

开发机暂时不可用时，E2–E10 在一次性训练任务容器中执行；镜像仍选官方 CUDA/PyTorch 镜像，不需要先做自定义镜像。

| 步骤 | 操作 | 校验 | 通过标准 |
|---|---|---|---|
| E1 | 确认算力点余额、资源规格与单价 | 控制台 | 能选到 A100-1-80G，余额够一次完整训练 |
| E2 | 准备运行容器：有开发机用开发机；否则提交一次性 A100 训练任务 | 容器终端 | `nvidia-smi` 显示 A100 80G |
| E3 | 探测环境：Python 版本、外网、`/data` 与 `/tmp` 空间 | 终端输出 | 能装依赖、`/data` 可写、`/tmp` 够放环境 |
| E4 | 用 micromamba/conda 建 Python 3.8 环境（建在 `/tmp`） | `python -V` | 输出 3.8.x |
| E5 | 安装 PyTorch 2.4.1+cu121 与 torchvision 0.19.1+cu121 | `torch.cuda.is_available()` | True |
| E6 | 先装 numpy 1.24.1，再从 `/data` 的安装包安装 Isaac Gym 与仓库依赖 | `import isaacgym` / `pip check` | 无报错、无冲突 |
| E7 | clone LeggedGym-Ex 并切到固定 commit | `git log -1` | commit 与记录一致 |
| E8 | 跑最小任务（10 迭代） | 终端输出 | 无异常退出 |
| E9 | 写 `docs/env-lock.md` 与 `/data/proj1/env-lock.md` | 人工检查 | 版本、commit、镜像/环境包齐全 |
| E10 | 打 `conda-pack` 环境包并记录 sha256 | 包存在 | 新任务可复用 |
| E11 | 提交 100 迭代训练任务做冒烟 | 任务日志 | 进入迭代、无 OOM、TensorBoard 有曲线 |

说明：

- Isaac Gym Preview 4 安装包需要 NVIDIA 账号下载（https://developer.nvidia.com/isaac-gym ），先在本地下载 `IsaacGym_Preview_4_Package.tar.gz`，再上传到云盘 `/data/proj1/env/`；不要解压后上传，也不要假设任务容器能绕过 NVIDIA 登录直接下载。浏览器可能保存为 `.tar`，bootstrap 同时接受 `.tar.gz` 和 `.tar`，并用 `tar -xf` 自动识别压缩格式。
- 环境建在本地盘 `/tmp` 再打包到 `/data`，避免在云盘上直接跑 Python 环境导致启动缓慢。
- `conda-pack` 示例：`conda-pack -p /tmp/py38 -o /data/proj1/env/isaacgym-py38.tar.gz`。
- 新任务使用环境包时，解包后先运行 `conda-unpack`，再激活环境。
- 一次性环境构建任务也用“本地上传”代码来源，代码包控制在 500 MB 内；Isaac Gym 安装包单独放 `/data`，不要塞进代码包。
- Isaac Gym 装好后要执行官方 Dockerfile 里的 `np.float` 修复（只替换独立的 `np.float`，不要误伤 `np.float32`），否则 numpy 1.24 下会报错。
- conda 的 Python 3.8 自带 `libpython3.8.so.1.0`，但直接运行 `<env>/bin/python` 时不在默认动态库搜索路径；必须在启动脚本里把 `<env>/lib` 和 `<isaacgym>/isaacgym/_bindings/linux-x86_64` 加入 `LD_LIBRARY_PATH`，否则会报 `ImportError: libpython3.8.so.1.0: cannot open shared object file`。

**2026-11-22 平台探测结论（已确认）：**

- GPU：A100-SXM4-80GB / 81920 MiB / driver 580.65.06 / compute capability 8.0
- 系统：Ubuntu 22.04.5 / glibc 2.35 / 128 核 / 1 TB 内存
- Python 3.11.13；conda 25.5.0、mamba 2.1.1 可用；系统没有 python3.8
- 外网：PyPI、PyTorch wheel 源、conda-forge、GitHub、NVIDIA 均返回 200
- 存储：`/data` 为 30 GB JuiceFS 且可写；`/tmp` 约 3.4 TB
- 缺少 `libGL`/`libGLU`/`libX11`，bootstrap 中用 apt 补；`xvfb`、`ffmpeg` 也需 apt 安装
- 平台已预设 `TENSORBOARD_LOGDIR=/train-events/jobs/<task-id>/tb/var/log/training`，训练脚本必须沿用这个值

### 2.6 训练任务使用规范

**代码来源**

- 首选 Git 仓库：平台把代码拉到 `/code/workspace`，启动命令按该路径填写。
- 上游 LeggedGym-Ex 用 submodule 或在启动脚本里 clone 到 `/code/workspace/third_party`。
- 仓库未就绪时可先用本地上传（≤500 MB），正式训练前必须推到 Git。
- 云盘代码来源只用于临时调试；正式训练必须能从 Git commit 重建。

**环境**

- 方案 A（推荐）：按 2.5 打 `conda-pack` 环境包放 `/data/proj1/env/`，任务启动时解包到本地盘、运行 `conda-unpack` 后激活。
- 没有开发机时，方案 A 的环境包由一个一次性训练任务产出，产物直接写 `/data/proj1/env/`。
- 方案 B：构建自定义镜像；这不是第一步，等环境包稳定后再考虑。平台最多 5 个镜像，构建时选 NVIDIA GPU 资源。
- 环境包必须与训练任务镜像同源；更换基础镜像后要重新打包并复测。
- 启动命令最多 500 字符，建议只写 `bash /code/workspace/scripts/train_job.sh`，细节放脚本里。

**启动脚本必须做的事**

1. 解包环境包到本地盘，运行 `conda-unpack`，设置 `PYTHONPATH` 与 `LD_LIBRARY_PATH`，再激活 Python 3.8 环境；
2. 沿用平台已设置的 `$TENSORBOARD_LOGDIR`，不要覆盖；LeggedGym-Ex 默认写自身 `logs/`，用同步循环把 `events.out.tfevents.*` 复制进去；
3. 把 stdout/stderr 同时写入 `/data/proj1/runs/<run-id>/job.log`；
4. 复制本次配置到 `/data/proj1/runs/<run-id>/configs/`；
5. 检查 checkpoint，存在 `--resume` 时从指定 checkpoint 恢复；
6. 训练结束把最终 checkpoint、评测 CSV 落到 `/data`；
7. 所有 Python 入口必须先 `import isaacgym`，再 `import torch`，否则会报 `PyTorch was imported before isaacgym modules`。

**断点续训**

- 每 50–100 次迭代保存一次 checkpoint，先写临时文件再原子重命名。
- 保存 `iteration`、`env_steps`、优化器状态、学习率调度状态、随机种子状态。
- 单任务上限 168 小时，按“分段训练”设计，每段结束前必须完成一次落盘。
- 停止后的任务不能原地继续，只能新建任务并从 `/data` 的 checkpoint 恢复。

**日志、监控与成本**

- 平台任务日志用于看启动失败和实时输出；`/data` 里的 `job.log` 用于长期留存。
- TensorBoard 必须写 `$TENSORBOARD_LOGDIR`，否则任务详情页没有曲线。
- LeggedGym-Ex 默认把曲线写到 `<repo>/logs/<experiment>/<timestamp>/`；训练脚本需周期性把 event 文件同步到 `$TENSORBOARD_LOGDIR`，任务结束时再做一次最终同步。
- 每个任务记录：任务 ID、资源规格、镜像/环境包、起止时间、算力点、最终迭代数。

**视频与回放**

- 训练任务容器无显示器，`play.py` 需要 `xvfb-run` 或改用无头评测。
- 视频优先在开发机或本地 T4 上录制；若都不行，用 MuJoCo/MJLab 做 sim2sim 回放并注明。

## 5. 测试验证标准

| 测试类型 | 方法 | 通过标准 |
|---|---|---|
| 启动测试 | 平台任务冷启动 | 排队结束后 5 分钟内进入迭代 |
| 显存测试 | 逐步提高 num_envs（1024→2048→4096） | 峰值 ≤ 64 GB，无 OOM |
| 数值一致性 | 同配置同种子跑两次 | 前 100 迭代 reward 趋势一致 |
| 评测一致性 | 同权重跑两次 eval | 关键指标差异 < 1% |
| 回放一致性 | 对比视频与曲线 | 无“指标好动作差” |
| 断点续训测试 | 中途停止任务，新建任务从 checkpoint 恢复 | 迭代连续、曲线不断裂 |
| 平台复现测试 | 同一镜像/环境包 + 同一命令重跑 100 迭代 | 曲线趋势与首跑一致 |
| 负向测试 | 故意改错关节顺序或观测维度 | 能快速报错而非静默错误 |
| 可复现测试 | 按 README 从零装一遍 | 能跑出同量级结果 |

## 7. 风险点与回滚方案

| 风险 | 触发条件 | 影响 | 预案 | 回滚动作 |
|---|---|---|---|---|
| 平台镜像不兼容 | 默认 Python 3.11 / CUDA 12 下 `import isaacgym` 失败 | 无法训练 | 用 2.5 的 py3.8 环境包或自定义镜像 | 回退到已验证环境包 |
| 任务内无法下载 Isaac Gym | 外网受限 | 装不上 | 提前把安装包上传 `/data` | 改用云盘代码来源 + 本地包 |
| 显存溢出 | OOM | 训练中断 | num_envs 降至 512/1024/2048 | 恢复上一版配置 |
| 训练不收敛 | reward 长期不涨 | 无结果 | 降难度、查奖励符号、查观测 | 回退到基线配置 |
| 课程不上升 | 地形等级曲线平 | 学不到复杂地形 | 检查课程阈值与跟踪奖励 | 关闭课程先跑平地 |
| 仓库依赖腐烂 | 安装失败 | 无法启动 | 换备选仓库 | 切回 legged_gym 基线 |
| 任务到期或被停止 | 168 小时上限或手动停止 | 训练中断 | 每 50–100 迭代存 checkpoint，分段训练 | 新建任务从 `/data` 续训 |
| 任务排队 | 长时间排队 | 进度延误 | 换资源规格或错峰提交 | 本地 T4 先跑通链路 |
| `/data` 空间不足 | 云盘默认 30 GB | 无法写 checkpoint | 只保留必要 checkpoint，旧结果下载后删除 | 申请扩容 |
| headless 无法录视频 | `play.py` 起不来 | 缺演示素材 | `xvfb-run` 或回开发机/本地 T4 | MuJoCo sim2sim 回放 |
| 算力点耗尽 | 余额不足 | 任务无法提交 | 记录单次成本，优先必要实验 | 申请配额或缩减实验 |
| 结果不可复现 | 重跑差异大 | 数据不可信 | 锁定种子、版本、环境包 | 回退到已冻结的 commit + 环境 |
| 曲线好动作差 | 回放抖动 | 结论不成立 | 以回放为准，查动作平滑项 | 回退到上一版奖励配置 |

**回滚三件套（必须常备）：**

1. Git tag：每个通过门禁的版本打 tag
2. 配置快照：每次训练前复制一份配置到 `/data/proj1/runs/<run-id>/configs/`
3. 环境快照：保存 `conda-pack` 包及 sha256，或记录镜像名与构建版本

## 8. 约束规则

### 8.1 必须遵守

1. 不自己搭仿真环境，只用现成仓库的环境与资产。
2. 不改上游核心代码；需要改行为时用配置或子类。
3. 每次实验只改一个变量。
4. 所有结论标注“仿真验证”。
5. 所有数字必须能在日志或 CSV 中查到。
6. 版本、commit、种子必须记录。
7. 正式训练必须在平台 A100-1-80G 任务中完成，结果表标注实际资源规格。
8. 所有产物写入 `/data`；`/code/workspace` 与家目录不作为交付物。
9. 每次任务必须记录任务 ID、镜像/环境包、算力点。
10. 长训练必须支持断点续训，单段不超过平台 168 小时上限。

### 8.2 可选优化

- 增加第二个随机种子
- 增加域随机化范围对照
- 增加 MuJoCo sim2sim 回放
- 增加动作平滑度、力矩峰值等动作质量指标

### 8.3 禁止操作

1. 禁止把论文或他人博客的数字写成自己的结果。
2. 禁止在未复现的情况下声称“复现了某方法”。
3. 禁止使用无许可证仓库的代码作为公开成果主体。
4. 禁止同时改多处配置后比较结果。
5. 禁止删除失败案例与异常日志。
6. 禁止在简历中写“真机验证”“量产落地”。
7. 禁止把开发机临时目录里的结果当作最终结果。
8. 禁止在 Ascend NPU 上运行 Isaac Gym。
9. 禁止无 checkpoint 直接提交超长训练任务。
