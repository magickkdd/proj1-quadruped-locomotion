# Intern Discovery 平台适配评估

| 项 | 内容 |
|---|---|
| 评估对象 | https://discovery.intern-ai.org.cn/docs/workbench/training |
| 评估时间 | 2026-11-22 |
| 结论 | 适合，且对项目一、项目二优于双卡 T4；项目三收益有限。项目一已确定以 A100-1-80G 为正式指标硬件 |
| 依据 | 官方文档：训练任务、科学计算概述、我的开发机（2026-10-30 更新） |

## 1. 平台能力摘要

| 能力 | 说明 |
|---|---|
| 开发机 | 在线 VSCode / JupyterLab，带 GPU，可开终端、克隆仓库、装依赖 |
| 训练任务 | 批处理任务，代码 + 镜像 + 数据 + 资源组合后托管运行 |
| 持久化 | 云盘挂载到 `/data`，任务结束仍保留；`/data` 之外停止即重置 |
| 临时代码目录 | Git 或上传的代码在 `/code/workspace`，不持久 |
| 代码来源 | Git 仓库、本地上传（≤500 MB）、我的云盘 |
| 运行时长 | 单次任务最长 7×24 小时（168 小时） |
| 监控 | 平台集成 TensorBoard，日志写入 `$TENSORBOARD_LOGDIR` |
| 计费 | 算力点，按资源规格单价 × 时长；配额可申请 5000/10000/20000 点 |
| 断点 | 任务停止后不能原地续跑，需“重新训练”并从 checkpoint 恢复 |

开发机文档列出的资源为：NvidiaA100-1-80G、NvidiaA100-8-80G、Ascend910B-1/8-64G、CPU-4C-16G；未见 T4。训练任务资源列表以控制台为准，项目一选 A100-1-80G，不使用 A100×8 和 Ascend NPU。单价与算力点余额需在页面确认。

## 2. 三个项目的适配结论

| 项目 | 适配度 | 原因 |
|---|---|---|
| 项目一 四足（Isaac Gym） | 高 | Isaac Gym 支持 Ampere，A100 训练吞吐远高于 T4；无相机渲染时不依赖 RT 核心 |
| 项目二 人形（mjlab / MuJoCo） | 高 | MJX / MuJoCo 在 A100 上运行良好，大显存可直接放大动作数与模型 |
| 项目二 人形（Isaac Lab / Isaac Sim） | 中低 | Isaac Sim 官方推荐 RTX 系列，A100 无 RT 核心，渲染相关功能有风险 |
| 项目三 机械臂（MuJoCo） | 中 | MuJoCo 以 CPU 仿真为主，A100 只加速策略训练；收益不如前两个项目 |

**因此：项目二在平台上应优先走 mjlab 路线，不要一上来选 Isaac Lab 3 版本。**

## 3. 对现有规格文档的增量要求

以下四条必须加进三个项目的执行流程。

### 3.1 先建自定义镜像，再跑训练任务

训练任务的启动命令最多 500 字符，且每次任务都是新容器。Isaac Gym 依赖重、版本敏感，不能每次 `pip install`。

做法：

1. 在开发机上完成环境搭建与冒烟
2. 构建并保存自定义镜像（平台支持“我的镜像”）
3. 训练任务直接选该镜像，启动命令只留训练脚本

### 3.2 所有产物写入 `/data`

必须落到 `/data` 的内容：

- checkpoint
- TensorBoard 日志（同时满足 `TENSORBOARD_LOGDIR`）
- 评测 CSV、结果表
- 配置文件快照
- 数据集与重定向后的动作

`/code/workspace`、家目录、`/tmp` 的东西任务结束即丢失。

### 3.3 训练必须支持断点续训

单任务上限 168 小时，任务不能原地续跑。每个训练脚本必须支持：

- 定期保存 checkpoint 到 `/data`
- 从指定 checkpoint 恢复优化器、学习率调度、环境步数
- 日志追加而非覆盖

### 3.4 开发机与训练任务分工

| 阶段 | 用哪个 |
|---|---|
| 环境搭建、依赖排查、小规模调试 | 开发机；不可用时用一次性短时训练任务 |
| 构建镜像 | 平台镜像功能；优先级低于 `conda-pack` 环境包 |
| 正式训练、批量消融 | 训练任务 |
| 结果查看 | 训练任务详情页 + TensorBoard |

开发机停止会重置 `/data` 以外所有文件，重要内容必须先落盘。开发机不可用时，环境构建任务本身也是训练任务：1×A100、官方镜像、代码本地上传、产物写 `/data`。

## 4. 与双卡 T4 方案的差异

| 维度 | 双卡 T4 本地 | Intern Discovery |
|---|---|---|
| 显存 | 16 GB/卡 | A100-1-80G，可放大动作数与模型 |
| 并行方式 | 同机两张卡各跑一个实验 | 提交两个独立任务，隔离更干净 |
| 环境 | 可长期保留 | 默认临时；用 `conda-pack` 环境包复用 |
| 调试 | 本地随时改 | 提交短任务，靠日志排查 |
| 中断风险 | 自己控制 | 有时长上限、可能排队 |
| 成本 | 电费/折旧 | 按算力点计费，A100 消耗快 |

**结论：本地 T4 适合日常调试，平台 A100 适合正式训练和批量实验。两者组合使用，而不是二选一。**

## 5. 使用前必须确认的六件事

1. 训练任务资源列表是否与开发机一致（A100-1-80G / A100-8-80G），以及 A100-1-80G 的单价
2. 当前算力点余额与可申请配额
3. 训练任务容器内是否有外网（能否 `git clone`、`pip install`）
4. 云盘容量上限，以及能否存放大规模动作数据与 checkpoint
5. 自定义镜像的构建方式与大小限制
6. 数据集许可证是否允许上传到第三方平台（尤其是动捕数据）

第 3 条和第 6 条最容易出问题，务必先验证再投入。

## 6. 建议的落地顺序

1. 提交探测任务，确认 A100 80G、外网、`/data`、`/tmp`（已完成，2026-11-22）
2. 提交一次性 bootstrap 任务，产出 `/data/proj1/env/isaacgym-py38.tar.gz`
3. 提交冒烟任务，跑 10–100 迭代，确认 TensorBoard 与 checkpoint
4. 提交平地与粗糙地形正式训练，分段续训
5. 项目二开始时再建独立的 mjlab/Isaac Lab 环境，不复用项目一的 py3.8 环境
6. 项目三用独立 MuJoCo 环境，CPU 仿真为主，A100 只用于策略训练

## 7. 对简历的影响

平台本身不是成果，但可以写进工程能力：

- 在 A100 上完成训练环境封装，产出可复用 `conda-pack` 环境包（后续可固化为镜像）
- 实现断点续训与产物持久化，支持 168 小时长任务
- 用平台完成多组消融的批量调度

不要写“使用 A100 训练”当作亮点，要写清楚解决了什么工程问题。

## 8. 多项目并行与共享边界

| 资源 | 能否共享 | 做法 |
|---|---|---|
| 平台账号、基础镜像、A100 资源池 | 可以 | 各项目提交独立训练任务 |
| `/data` 云盘 | 可以，但要分目录 | `/data/proj1`、`/data/proj2`、`/data/proj3` |
| conda / `conda-pack` 环境 | 不建议 | 项目一 py3.8 + Isaac Gym 单独一套；项目二 mjlab/Isaac Lab 单独一套；项目三 MuJoCo 单独一套 |
| 代码仓库 | 可以同账号、不同仓库 | 不要把项目二/三代码装进项目一的 vendor 目录 |
| TensorBoard | 平台按任务隔离 | 每个任务用自己的 `$TENSORBOARD_LOGDIR`，不要手动混写 |
| checkpoint / 结果 | 不共享 | 每个项目独立 `runs/` 目录 |

并行注意：

- 任务级隔离：每个训练任务独立容器、独立 GPU、独立 `/tmp`，软件层面互不影响。
- 资源级竞争：同时跑 3 个 A100 任务会 3 倍消耗算力点，也可能排队。
- 存储：云盘默认 30 GB，三个环境包 + checkpoint 可能不够；先只保留当前项目的环境包，其他放本地或申请扩容。
